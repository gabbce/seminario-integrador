# Protocolo ejecutable I-06.3

Se valida el mismo JAR/React de la imagen Compose con PostgreSQL 17.6 y un emisor JWKS de prueba en una red Docker interna. La aplicación se conecta además a un bridge propio para publicar su puerto en loopback; ese bridge permite egreso, por lo que no se afirma bloqueo total de salida de red. El guion y su configuración apuntan exclusivamente a los servicios locales y no reciben credenciales remotas. El backend valida firmas RSA, issuer, audience, caducidad y perfiles persistidos mediante su cadena de seguridad normal. Cincuenta identidades/sesiones distintas: 45 Docente, 2 Admin y 3 Bedel. No se conecta a Supabase ni se usan credenciales remotas. Esto mide el paquete y la base local, no acredita los RNF contra Supabase: la limitación remota I05 sigue declarada.

Dataset determinista (semilla `i06-load-v1`), año histórico cerrado = año de ejecución menos uno, operativo habilitado = año de ejecución más uno. Dos cuatrimestres de 16 semanas por año, 200 series/cuatrimestre de dos días (32 detalles) y 500 esporádicas entre días lectivos/recesos; 30 aulas (10 por tipo), capacidades/estados variados, sin solapamientos. Registrar tamaño inicial, IDs, fechas/filtros y hash del generador. Los casos pequeños exactos permanecen en su entorno independiente.

Preparar antes de medir propuestas de altas, versiones y dos series propias por sesión operativa (cuatrimestral/anual). Cada operador dispone de dos aulas generales y asignaciones exclusivas, suficientes para el límite teórico del guion. Altas alternan cuatrimestral/anual; modificaciones alternan ambas series y cambian todos sus patrones entre las dos aulas predefinidas, actualizando la versión devuelta. No compartir franjas entre operadores ni con el volumen base. Listados solicitan página 0, tamaño 20. Disponibilidad consulta dos patrones en el año operativo.

Arranque escalonado de sesiones cada 100 ms. Cuando las 50 están activas, 120 segundos de calentamiento; después 600 segundos de medición, sin reiniciar sesiones/ciclos. Circuito cerrado, exactamente 5 segundos de espera programada tras cada respuesta completa; registrar espera efectiva. Una operación por sesión; no tasa forzada. Docente: disponibilidad, listado diario, disponibilidad, listado por curso. Operador: disponibilidad, alta, disponibilidad, modificación. Las preparaciones iniciales y emisión/autenticación quedan fuera de percentiles; auxiliares durante el guion, si existen, se registran separados.

Guardar cada muestra con sesión/rol/operación/fase/duración/HTTP/tipo de error; no excluir errores ni outliers. Percentiles por operación y tasa efectiva sobre 600 s; pausas, ciclos, reparto cuatrimestral/anual, recursos Docker/equipo, versión imagen/JVM/PG y topología/latencia de red. p95 disponibilidad/listados <1500 ms; altas/modificaciones periódicas <2000 ms. Conflictos intencionales se verifican aparte; nominal debe estar libre de colisiones artificiales. Fallos o limitaciones se informan y corrigen, sin acortar carga ni reescribir umbrales.
